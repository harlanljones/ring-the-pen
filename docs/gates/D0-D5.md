## D1 — BvP / shrink (`k=20`) and D1b lineup reconstruction

**Requirement D1 (frozen by DEC-7).** BvP rates come from the frozen artifact,
never a live scrape. The estimate is a **credibility blend**
`posterior = (n·x̄ + k_shrink·m)/(n + k_shrink)`,
`Z = n/(n + k_shrink)`, with prior `m` an odds-ratio expected rate (batter's
regressed overall rate adjusted to the pitcher's hand × pitcher's regressed
allowed rate adjusted to the batter's hand), 3-year Marcel 5/4/3 window (~1200 PA
regression), platoon components regressed with 1000/2200 PA (batter) and ~700/450
BFP (pitcher) constants. Weights `w_bvp = n/(n+k_shrink)` and
`w_prior = k_shrink/(n+k_shrink)` are exposed and shown. The `k=20` pin is split:
`k_display = 20` (provisional underqualified gate) and `k_shrink` (fitted; ~1000
PA placeholder labeled `uncalibrated` until fitted). See
`docs/decisions/0007-bvp-shrink.md`.

**Requirement D1b.** The next **N=3** batters are reconstructed from the source
lineup and substitutions. Historical (event-file `start`/`sub` records, batting
order wrap, pinch-hitter handling) and live (Stats API on-deck/lineup) are
distinct paths; the historical path ships first. The exact scope is frozen by
**DEC-9**.

**CHECK (RTP-06, RTP-08).**
`mix test test/ring_the_pen/shrink_test.exs` and the ETL unit suite.
**EXPECT.** Hand-computed fixtures at the `pa_vs = 19/20/21` boundary; weights
present and summing as specified in DEC-7; N=3 reconstruction test including an
order wrap and a substitution; a missing-platoon case stays explicit, never zero.

**Blocked on.** DEC-3/4/7/9 **all decided**; the TG milestones still gate the
actual formulas. Status: `OPEN` (runnable once RTP-06 lands).

## D2 — Pitch unknown / universe A

**Requirement.** Universe A is `pa=1 AND nump>0`. The unknown pitch-count class
is `pa=1 AND nump ∈ {blank, 0}` and is an explicit **unknown** state, excluded
from pitch counts and never coerced to 0. In raw event files, a blank 6th (`play`)
field is overwhelmingly an `NP` (non-PA) record and must not be read as an unknown
plate appearance; the code always gates on the `pa` flag. Which source is
authoritative (event files vs `2025plays.csv`) is frozen by **DEC-3**.

**CHECK (RTP-05, RTP-17).**
`make data && python3 -m unittest discover -s tests -v` plus the falsifier suite.
**EXPECT.** ETL reports a frozen universe A row count; the count of the unknown
class matches the pinned candidates (513) or the ETL records why not; negative
test: a blank/absent `nump` never yields a pitch count of 0, and an `NP` blank is
never counted as an unknown PA.

**Blocked on.** None — DEC-3/DEC-4 decided and RTP-05 core passed (`make data`
byte-identical; 7 Python tests). Status: `OPEN` (cross-check artifact produced;
the `cwevent` reconciliation agrees on all 2,430 common games).

## D4 — Lock (confidence lock; Choice/Score primary, Noul secondary)

**Requirement.** The confidence lock routes each card to `act | review |
escalate` from the typed answers, using the predecessor `SabrJev.Latch` mechanism
(Choice/Score drive all three routes; Noul is `act`/`review` only and never
escalates a card on its own; `other` → escalate; an underqualified sample can
never `act`). Hard code gates (pitch cap, injured, empty pen) are not overridable
by Jev. Thresholds τ are **provisional** and labeled as such in the UI and
`/about` unless a calibration report exists. Threshold values are frozen by
**DEC-5**. Every card route passes the lock; "no lock, no demo".

**CHECK (RTP-11, RTP-13, RTP-17).**
`mix test test/ring_the_pen/lock_test.exs` and the workbench LiveView tests.
**EXPECT.** Every recorded card yields a lock route from frozen recordings;
underqualified sample never routes `act`; Noul alone never escalates; thresholds
shown as `provisional`; falsifier "no lock" exercised.

**Blocked on.** DEC-5 **decided** (`docs/decisions/0008-lock-thresholds.md`;
0.8/0.5 Choice/Score, 0.85 Noul, provisional). Status: `OPEN` (runnable once
RTP-11 lands).

## D5 — Brier / uncalibrated honesty

**Requirement.** Where a next-PA/window Noul is recorded, an evaluation report
reports Brier by class against a **frozen baseline** with reliability buckets,
coverage, and missingness. Baselines are fixed before predictions and never fit
on outcomes. Until outcomes exist the report says **"prospective, accuracy
pending"** and no calibration or accuracy claim is made. Missing outcomes stay
pending/excluded, never negative labels.

**CHECK (RTP-16).**
`mix test test/ring_the_pen/evaluation_test.exs` plus refusal tests.
**EXPECT.** Report contains Brier by class, baseline Brier, reliability buckets,
coverage/missingness, and an explicit "accuracy pending" status; refusal tests for
historical enrollment, late capture, tampered ledger, and mixed cutoffs.

**Blocked on.** None beyond RTP-11; baseline values are `TBD` and established by
RTP-16. Status: `BLOCKED` (report not built).
